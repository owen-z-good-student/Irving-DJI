1这是什么

FH2 集成技能是一个装在 AI 编码助手里的「领域专家包」。装上之后，当你向 AI 提出司空 2 相关的集成需求时，它会按照一套经过验证的方法论来回答，而不是凭记忆猜测。

它解决什么问题

没有它有了它
AI 可能编造不存在的 API 端点强制反幻觉：不确定就说不确定，并指向官方文档核验
把公有云和私有化的接口混着用先确认部署形态，严格区分 API 边界
把应急出警的做法套到日常巡检上先确认场景，两类工作流分别设计
官方文档分散，不知道从哪查起按能力域整理好的选型表 + 需求↔端点匹配
生成的代码缺安全护栏内置验签、幂等、权限、审计等最低要求
一句话 它不替你写业务代码，而是保证 AI 在司空 2 这个领域里不乱说、不越界、不漏安全项。

3安装

把整个 fh2-integration-skill/ 目录放到你的 AI 助手技能目录下即可，无需额外依赖。

Claude Code / OpenCode

# 放到本地技能目录（具体路径取决于你的环境）
~/.claude/skills/fh2-integration-skill/
# 或
~/.config/opencode/skills/fh2-integration-skill/

之后直接提问司空 2 / DFR / 巡检相关问题即可自动触发。

Cursor

把 adapters/cursor-rules.md 里的内容复制成项目规则文件：

.cursor/rules/fh2-integration.mdc
可选：挂载 OpenAPI MCP 如果你的环境接入了司空 2 / Apifox 的 OpenAPI MCP，本技能会优先通过 MCP 读取真实端点与结构来做需求匹配和改代码，而不是让你自己翻文档。没有 MCP 时会回退到官方文档链接。两种情况下都不会编造端点。

4核心机制：两道门

这是本技能最重要的设计。AI 在给出任何 API 建议之前，必须先通过两道门。

第一道 · 部署 Gate
你的司空 2 是哪种部署形态？公有云 / 私有化 / AIO 一体机
决定 API 范围与认证模型。三者的接口能力面并不相同。
↓
第二道 · 场景 Gate
你要集成哪类工作流？DFR 应急响应 / 巡检巡逻 / 两者都要
决定接口选型、数据流与安全关注点。
↓
才开始给方案
架构设计 · 接口映射 · 实施计划 · 安全护栏 · 测试计划
为什么 AI 会「先问你问题」而不是直接给答案 这是刻意设计的。部署形态不同，可用的 API 完全不同；场景不同，该选的接口也不同。技能被明确禁止从 token 格式、URL、域名、区域等线索去推断部署形态——猜错的代价是给你一套跑不通的方案。

两类场景的差异

维度DFR / 应急巡检 / 巡逻
触发源外部告警、CAD 接处警计划、定时、周期
时效秒级应急常态周期
主接口自动派遣工作流航线 + 计划任务
数据流重点实时直播、人工接管采集 → 分析 → 共享
后处理现场处置、证据归档AI / VLM 缺陷识别、三维重建

5能帮你做什么

DFR / 应急响应

  • CAD、告警系统 → 司空 2 出警派遣中间件
  • 无人机直播接入 VMS / 指挥中心大屏
  • 遥测数据接入 GIS / PSIM 态势平台
  • 媒体与证据归档管道

巡检 / 巡逻

  • 航线上传、同步到司空 2 航线库、计划任务下发
  • 巡检媒体 → AI / VLM 缺陷分析 → 第三方平台
  • 三维重建 / 点云成果同步

通用

  • Event API 回调接收与处理
  • FlightHub Sync / OpenAPI / MQTT Bridge 接口选型
  • 公有云与私有化的 API 边界核对
  • 把司空 2 能力接进你已有的平台（适配层设计）
  • 实施计划、测试计划、安全护栏

6怎么提问

不需要特殊语法，正常说需求即可。以下示例可直接复制。

能力咨询

我们想用无人机做变电站巡检，司空 2 能提供哪些能力？帮我理一个方案。

DFR 集成设计

我们用司空 2 公有云，帮我设计一个 CAD 告警到出警派遣的中间件。

巡检集成设计

我们是私有化部署，设计一个变电站定时热成像巡检的任务下发中间件。

对接已有系统

我们已经有一套运维平台，想把司空 2 能力接进去，而不是再上一套独立系统。

找端点、改代码

我要做直播接入，帮我看看哪些端点能对上，产出一个需求↔端点匹配表。
小技巧 如果你已经知道部署形态和场景，在第一句就说明（例如「我们是私有化部署，做巡检」），可以跳过两道门的追问，直接进入方案设计。

快速启动

# 后端
cd examples/dfr-public-cloud-demo/backend
npm install && npm start        # 默认 http://localhost:3000

# 前端（另开终端）
cd examples/dfr-public-cloud-demo/frontend
npm install && npm run serve

详细步骤见 Demo 目录内的 QUICKSTART.md，上云部署见 deploy/README.md。

本地就能试用真实接处警，不用买服务器 只要有司空 2 组织密钥，本机 localhost 就能下发真实出警派遣——无需云服务器、无需公网 IP、无需内网穿透。 因为派遣是纯出站请求（浏览器 → 本地后端 → 司空云），穿 NAT 无障碍。 这是从「看文档」到「看机场开舱」最快的一条路。
功能流量方向纯本地
出警派遣你 → 司空云✅ 可用
Event API 回调司空云 → 你❌ 需公网入口
MQTT 遥测司空云 → 你的 broker❌ 需公网入口
航线同步司空云 → 你的 S3 桶❌ 需公网入口

后三项需要司空 2 主动连进你的机器，可用 ngrok / cpolar 内网穿透解锁。

派遣会驱动真实设备 这不是模拟——机场会真实开舱、无人机会起飞。下发前请确认空域合规、现场有人监护，并优先使用测试机场。

你需要准备

  • 组织密钥：司空 2 → 我的组织 → 组织设置 → OpenAPI → 复制密钥
  • 项目 UUID：调用「获取组织下的项目列表」接口获取
  • （可选）MinIO / S3、MQTT broker、推流服务器
Demo 是教学级，不是生产级 它刻意省略了部分生产必需项（如 Event API 验签、数据库存储），用于降低理解成本。直接用于生产是不安全的。务必阅读 Demo 目录下的 LIMITATIONS.md，其中列出了全部已知局限和生产化清单。
关于地图 Demo 会根据你的浏览器语言自动选择底图（中文用户用高德，其他用谷歌）。所有底图都会提示坐标系偏移风险——地图位置不等于无人机实飞位置，务必以机场位置为基准。另外 Demo 使用的谷歌瓦片是非官方接口，仅供演示，生产须换用官方 API。

8安全边界

技能内置了一批强制约束，理解这些能帮你更好地判断 AI 输出的可信度。

AI 会主动停下来的情况

触发条件需要你确认
部署形态未知公有云 / 私有化 / AIO
认证模式不明Token / OAuth / SSO，哪些是占位符
涉及飞控、派遣、载荷、设备配置授权环境、人工介入、安全评审路径
要操作真实客户系统明确授权与目标环境
端点未在文档中确认请你到官方文档核验

绝对不会做的事

  • 编造端点、请求字段、事件类型、MQTT topic
  • 混用公有云与私有化的 API
  • 给公有云推荐仅私有化支持的能力
  • 把 AI 识别结果当作可直接执行的处置依据
  • 省略人在回路、地理围栏等飞行安全约束
如果 AI 说「我无法确认这个能力」 这不是能力不足，而是设计如此。相比编一个看起来合理但跑不通的端点，明确告知不确定并指向官方文档，对你更有价值。

10常见问题

为什么 AI 总是先反问我，不直接给答案？

因为部署形态和场景会根本性地改变可用接口。这是技能的核心设计，不是啰嗦。你可以在第一句就说明这两点来跳过追问。

技能里的知识文件是英文的，能翻译吗？

面向人的文档（README、使用指南、评估手册、Demo 文档）都有中文版。SKILL.md 和 references/ 是给 AI 读的行为约束，刻意保持英文——英文指令的遵循精度更高，且避免中英不同步产生冲突规则。需要理解某个文件时，直接让 AI 用中文给你讲解即可。

AI 给的端点能直接用吗？

不能直接用于生产。技能会标注哪些需要核验。请务必对照官方 Apifox 文档确认确切的请求体、响应字段和权限要求后再上生产。

Demo 能改成我们自己的系统吗？

可以，但建议把它当作适配层骨架而非成品。参考 Demo 目录下的 ARCHITECTURE.md，其中有各模块与知识库的映射关系，以及从演示到生产需要补齐的项。

私有化部署也能用这个技能吗？

可以。技能同时覆盖公有云与私有化/AIO，并会严格区分两者的接口边界。但要注意配套 Demo 是按公有云写的，私有化的接口面更广、认证方式可能不同，不要直接照搬 Demo 代码。
