# 在 Claude Code / OpenCode 中使用本技能

*[English](./claude-code-usage.md) | 中文*

最后更新：2026-07-09

## 安装方式

把整个 `fh2-integration-skill/` 目录放到你本地的 Claude / OpenCode 技能目录下（具体路径取决于你的环境），然后通过提问「司空 2 / FlightHub 2 / DFR / 巡检 集成设计」来触发它。

## 示例提问

**DFR / 应急场景**

```text
用 FH2 集成技能，帮我设计一个 CAD 到司空 2 的出警派遣中间件。
```

```text
我们用司空 2 公有云，帮我设计 DFR 场景下的 VMS 直播接入方案。
```

**巡检 / 巡逻场景**

```text
用 FH2 集成技能设计一个巡检中间件：让操作员上传航线、同步到司空 2 航线库，然后跑变电站定时热成像巡检。
```

```text
我们是司空 2 私有化部署，设计一下巡检媒体如何流转到我们的第三方 AI 缺陷分析平台。
```

**能力咨询（不懂二开）**

```text
我们想用无人机做园区安防，司空 2 大概能提供哪些能力？帮我理一个方案。
```

**对接已有系统**

```text
我们已经有一套公有云运维平台，想把司空 2 的能力接进去，而不是再上一套独立系统，怎么做？
```

## 预期的首轮行为

如果没有说明部署形态，助手应当**先问部署 Gate**：

```text
你要集成的司空 2 是哪种部署形态？

1. 司空 2 公有云
2. 司空 2 私有化部署
3. AIO 一体机
```

部署确定后，如果场景不明确，应当**再问场景 Gate**：

```text
你要集成的工作流类型是？

1. DFR / 应急响应
2. 巡检 / 巡逻
3. 两者都要
```

> 这两道门是本技能的核心约束。助手**不应**从 token 格式、URL、域名、区域等线索去推断部署形态。

## 推荐的后续追问

部署与场景确认后，助手应继续了解：

- **目标平台**：CAD / VMS / GIS / PSIM / 证据系统 / 大屏 / AI 分析平台
- **集成域**：出警派遣 / 航线 / 计划任务 / 直播 / 遥测 / 媒体 / 事件 / 前端组件
- **项目阶段**：PoC / 集成验证 / 安全评审 / 生产部署
- **期望产出**：架构设计 / API 映射 / 实施计划 / 代码骨架

## 关于 OpenAPI MCP

如果你的环境挂载了司空 2 / Apifox 的 OpenAPI MCP，本技能会**优先通过 MCP 读取真实端点与 schema**，用于需求匹配和改代码，而不是让你自己去翻网页文档。

没有 MCP 时，会回退到 Apifox 文档链接并提示你自行核验。**两种情况下都不会编造端点。**

## 三类典型用法

| 你的情况 | 建议怎么问 | 期望产出 |
|---|---|---|
| 不懂二开，想先了解能力 | "我们想做 XX，司空 2 能提供什么能力？" | 能力菜单 + 多轮引导 + 适合你的方案 |
| 略懂，想快速演示 | "我想快速跑个 Demo 给领导看" | 引导你到 `examples/dfr-public-cloud-demo/` |
| 懂二开，卡在文档分散 | "我要做 XX 功能，帮我看哪些端点能对上" | 需求↔端点 match 表 + 缺口清单 + 改哪些文件 |
