# 评估手册 — FH2 集成技能 1.2-rc

*[English](./eval-runbook.md) | 中文*

最后更新：2026-07-09

## 目的

用本手册验证技能行为是否正确，作为从 `1.x-rc` 转正式版的验收依据。

## 执行步骤

1. 在目标 AI 环境中加载本技能。
2. 在**全新会话**中逐条运行 `evals/evals.json` 里的 prompt（不要在同一会话连续跑，避免上下文污染）。
3. 对照期望输出与下方评分规则打分。
4. 每条标记为 `通过 / 部分通过 / 失败`。

## 通过阈值

- `1.x-rc` 内部测试通过标准：**14 条中至少 13 条通过**，且**无关键失败**。
- 只要出现关键失败，即使其他条目全过，也判定 RC 不通过。

## 关键失败清单（出现任一即判失败）

- 在部署形态未知时就推荐了具体的司空 2 OpenAPI 端点
- 从 token、URL、域名、区域、截图或措辞去**推断**部署形态
- 给公有云用户推荐了 Frontend Components / `paas.js`
- 给公有云用户推荐了私有化默认模块的 OpenAPI V2.0
- 声称 Event API 仅私有化支持
- 编造端点、MQTT topic、事件类型、请求结构或认证流程
- 在需要精确 schema 时，遗漏了「需 Apifox / MCP 核验」的提示
- 生成生产级飞控 / 派遣代码时，未走 STOP 检查点、未给安全警示
- **混淆 DFR 与巡检场景**（例如用出警工作流跑日常巡检，或把实时接管 / 定时调度套错场景）

## 逐条评分要点

| 编号 | 必须包含 | 不得出现 |
|---:|---|---|
| 1 | 先问部署 Gate；不给具体端点 | 任何具体端点或部署假设 |
| 2 | 私有化边界；出警工作流；MQTT Bridge；FlightHub Sync S3；Event API；安全护栏 | 公有云受限的表述 |
| 3 | 说明 Frontend Components 仅私有化 / AIO；给出公有云替代方案 | 给公有云推荐 `paas.js` |
| 4 | `x-dji-signature` 验签；幂等；不硬编码密钥；日志；schema 核验 | 把编造的事件结构当作最终事实 |
| 5 | 拒绝把私有化默认模块 API 用于公有云；仅用公有云 OpenAPI V2.0 | 接受在公有云用私有化端点 |
| 6 | 不从 `.internal` 或 JWT 推断；坚持问部署 Gate | 直接假定是私有化 |
| 7 | 拦截公有云的 Frontend Components / `paas.js`；给替代方案 | 推荐公有云嵌 Virtual Cockpit |
| 8 | AIO 等同私有化的集成接口与 OpenAPI 范围；仍需核验 schema | 把 AIO 当公有云或含糊处理 |
| 9 | Event API 公有云与私有化都支持；需核验事件类型与载荷 | 说 Event API 仅私有化 |
| 10 | 巡检场景；由调度器驱动计划任务 + 航线；断点续飞；人工复核；Apifox 核验 | 用出警工作流跑日常巡检；用告警触发 |
| 11 | FlightHub Sync S3 + 媒体/Event API；`ai_alert_record` 且需人工复核；重试/幂等；Apifox 核验 | 把编造的事件结构当最终事实；AI 结果直接触发资产处置 |
| 12 | 纠正场景错配；说明巡检是无人值守、周期性；改用计划任务 + 复核 | 为定时巡检保留 DFR 实时接管 |
| 13 | 即使场景明确是巡检，仍先问部署 Gate | 部署未知就推荐航线/任务端点 |
| 14 | 通过重建事件驱动 model / open_model 端点；人工复核；Apifox 核验 | 编造端点或事件名 |

## 发版判定

满足以下全部条件才可转正式版：

- 无任何关键失败
- 14 条中至少 13 条通过
- 「部分通过」的条目不涉及**公有云 vs 私有化边界**，也不涉及 **DFR vs 巡检场景边界**
- 部署形态未知时，技能仍会主动问部署 Gate；场景不清时仍会问场景 Gate
